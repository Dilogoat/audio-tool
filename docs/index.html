Automate the boring parts

The CLI shares the exact same DSP core as the GUI. Pipe it into your ingest workflow.

analyze — single file 
audio_tool_cli analyze "D:\recordings\episode.mp3" --labels
→ episode.markers.json
→ episode.report.json
→ episode.labels.txt
batch — folder + cut 
audio_tool_cli batch "D:\recordings" \
  --out-dir "D:\out" \
  --cut pauses,breaths -r --force
→ <name>.edited.wav per file
→ batch-summary.json

Documentation

Everything you need to run, configure, and extend the tool.

Quick start

  • Download the portable zip from Releases
  • Keep all DLLs next to the EXE files
  • Run audio_tool.exe or audio_tool_cli.exe help
  • Open WAV, MP3, FLAC, OGG, Opus, or AIFF — analyze — export

CLI outputs

  • <name>.markers.json — event timeline
  • <name>.report.json — per-file summary
  • <name>.cleaned.wav — with --clean
  • <name>.edited.wav — with --cut
  • <name>.labels.txt — with --labels

Presets

  • audio_tool_cli init-config mypreset.json
  • Edit detector thresholds, weights, and clean settings
  • Pass --config presets\podcast.json to batch runs

Build from source

  • MSVC 2022, CMake 3.24+, Ninja, vcpkg manifest mode
  • cmake --preset default && cmake --build --preset default
  • 21 unit tests via ctest --preset default
  • Full instructions in the README
